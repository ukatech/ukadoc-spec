# `\![timemachine,set,値]`

**カテゴリ:** 未分類コマンド

「現在時刻の仮想的変更」（タイムマシン）の差分を、指定した値にする。ゴーストから見える現在時刻（`system.year` などのプロパティ、[OnSecondChange](../../shiori-event/time/OnSecondChange.md) などの時刻のイベント、カレンダーの予定など）がずれる。日付や時刻に依存するゴーストの試験用。<br />
SSPを `--allow-timemachine-control` 付きで起動したときだけ有効。付けていないときは何もせず、エラーログに警告を記録する（ゴーストのスクリプトから、全体の時計を動かされないため）。認可されていないSSTP（外部からのSSTP）からは実行できない。<br />
差分はその起動中だけのもので、設定には保存されない。いまの差分に足すのではなく、差分をこの値にする（同じ指示を何度実行しても結果は同じ）。

- **値**: 差分の指定。次のいずれか。値が省略されたとき、解釈できないときは、エラーログに警告を記録して何もしない。
  - `+秒` / `-秒`: 差分そのもの（秒数）。符号は必須。例: `+86400`（1日先）、`-3600`（1時間前）
  - `0`: 差分を0にする（実際の時刻のまま）
  - ISO8601形式の日時: その日時になるように、実際の時刻との差を求めて差分にする。ゾーンの指定がなければローカル時刻とみなす。時計は止まらず、その日時から進み続ける。例: `2026-12-31T23:59:50`

差分の大きさは約200年まで。秒未満は切り捨てる。<br />
時刻を跳ばしたとき、跳んだ先の分や時が跳ぶ前と違えば、次の1秒の処理で[OnMinuteChange](../../shiori-event/time/OnMinuteChange.md) や [OnHourTimeSignal](../../shiori-event/time/OnHourTimeSignal.md) などが発生する（過去へ跳んだときも同じ）。<br />
自動更新などの間隔の計測、ログ、通信など、実際の時刻で動くものは影響を受けない。

!!! note "注"
    起動オプション `--time-shift` でも、起動時の差分を指定できる。現在の差分は、プロパティ `system.os.timeshift` で読める。

**対応:** SSP 2.9.39

## 記述例

```sakurascript
\![timemachine,set,2026-12-31T23:59:50]
```

2026年12月31日の23時59分50秒にして、そこから時計を進める。年またぎのイベントを試すときなどに使う。

```sakurascript
\![timemachine,set,+86400]
```

実際の時刻の1日先にする。
