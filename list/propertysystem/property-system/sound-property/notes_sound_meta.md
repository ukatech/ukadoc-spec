# サウンドプロパティのメタデータ（meta.～）について \[2.8.73\]

meta.で始まるサウンドプロパティは、メディアファイルに埋め込まれたタグ情報（ID3、Vorbis Comment、MP4のメタデータatom、ASFの属性など）を取得する。すべて読み取り専用。

**タグが存在しない場合や、何らかの理由で取得できなかった場合は、そのプロパティ自体が存在しないものとして扱われる。**[error](sound.error.md)のように空文字列が返るのではなく、プロパティの参照自体が失敗する点に注意（存在しないプロパティ名を指定した場合と同じ挙動になる）。タグの有無が不定のメディアを扱う場合は、この前提でスクリプトを書くこと。

なおタグを持たないフォーマットでは、当然ながらすべてのmeta.プロパティが取得失敗となる。

\[2.9.32\] MP3などのID3（v1 / v2.2 / v2.3 / v2.4）、FLAC・Ogg Vorbis・Opusのコメント、WAV・AVIのINFO（WAVのid3チャンクを含む）のタグは、OSに頼らずSSPが自分で読む。OSが読み誤る場合（OSの標準の文字コードで解釈してしまうShift_JISやISO-8859-1のタグ、unsynchronisationや拡張ヘッダの付いたID3v2、ID3v2.2、WAVのタグなど）も読める。SSPが読めなかった項目と、それ以外の形式（MP4・WMAなど）は、従来どおりOSから取得する。<br />
文字コードの指定が無いタグ（ID3v1、ID3v2のISO-8859-1、WAV・AVIのINFO）は、SSPが UTF-8 → Shift_JIS → OSの標準の文字コード の順に推定する。推定なので、特に日本語以外のOSでは、西欧語と日本語の取り違えが起きうる。<br />
取得は項目ごとに、まずSSPが読み、読めなかった項目だけをOSやメディアの再生用の部品から補うようになった。そのため、あるタグで一部の項目だけが取れても、残りの項目はOSやメディアの再生用の部品から補われることがある（その結果、アルバムアーティストが無いタグで、アーティストと同じ値が補われる環境がある）。
