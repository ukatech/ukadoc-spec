# Options for sound play/load/option

- **--volume=0～100**: Change the playback volume. Max is 100. This does not control the overall OS volume.
- **--balance=-100～0～100**: Left/right balance. -100 is fully left; 100 is fully right.
- **--rate=1～100～10000**: Playback speed. 100 is normal speed.<br />
  The actual available range depends on the sound driver implementation, etc. Values around 400 or higher (435 or higher) often cause an error.
- **--seektime=時刻 \[2.8.70/72\]**: Specify the playback start position. For play, playback starts after seeking to the specified position. For option, if playback is in progress, it jumps to that position and continues playing; if paused, it seeks internally to that position and waits (playback does not start).<br />
  For load, the sound waits after seeking to the specified position, and that position is retained until the next play. However, specifying load again for a file that has already been loaded does not change the position. Use option in that case.<br />
  There are two time formats. Without “:”, the value is an integer in milliseconds; with “:”, it is interpreted as \[\[hours:\]minutes:\]seconds\[.milliseconds\]. “90500”, “1:30.5”, and “0:01:30.5” all indicate 1 minute and 30.5 seconds.<br />
  Up to three digits (milliseconds) are allowed after the decimal point; any fourth and subsequent digits are truncated. Unparseable formats and negative values are treated as 0 (the beginning).<br />
  Some file formats cannot be seeked. In that case, the option is ignored and playback starts from the beginning. In particular, wav files support seeking only for uncompressed PCM/IEEE float; compressed wave formats such as ADPCM cannot be seeked.<br />
  Prefix the value with @ to specify a relative position from the current playback position. Negative values can be specified in this case.
- **--window=false/true (=OFF/ON)**: Whether to display a window with a seek bar. If true, the window is forced to display even for audio only. If not specified, it is hidden for audio only and shown for video.
- **--sound-only=false/true (=OFF/ON)**: Only applies to load: allows playing only the audio of a video file. If not specified, the behavior is the same as false.
- **--spectrum=間隔 \[2.9.18\]**: Notify the spectrum of the sound during playback (volume levels for each frequency band) at the specified interval (in milliseconds), using the [OnSoundSpectrum](../../shiori-event/other/OnSoundSpectrum.md) event. The allowed range is 20–1000; values from 1 to 19 are clamped to 20, and values of 1001 or higher are clamped to 1000. \[2.9.33\] On Windows 10 (1803) and later, the interval is timed precisely and notifications arrive as specified (the period does not drift even if processing is delayed; if the ghost cannot keep up, notifications are skipped rather than queued). In 2.9.32 and earlier, and on older OSes, the actual interval depends on the OS timer resolution (usually about 15.6 milliseconds); shorter intervals are less likely to match the specified value (100 means about every 111 milliseconds). 0 (and negative values) stops notifications. No notifications are sent if this option is not specified.<br />
  Notifications can be started, stopped, or have their interval changed at any time with option, even during playback. If started partway through playback, band levels may be reported slightly low for a short time immediately afterward.
- **--spectrum-bands=0/5/10/15/31 \[2.9.18\]**: Number of bands reported by --spectrum=. Specify one of 0, 5, 10, 15, or 31 (other values are rounded to the nearest option; for example, 16 becomes 15, 20 becomes 15, and 64 becomes 31). Defaults to 10. Can be changed during playback.<br />
  \[2.9.19\] Setting this to 0 skips analysis by frequency band and reports only the overall volume level for each channel (Reference2 and 3 of [OnSoundSpectrum](../../shiori-event/other/OnSoundSpectrum.md)) and the playback position (Reference6). This can be used to report elapsed time with volume levels. The playback position is also reported for sounds such as MIDI and CD tracks, from which a waveform cannot be extracted (volume is 0).<br />
  The frequencies of each band are determined by a fixed table for each number of bands, as shown in the [table below](bang-sound-option.note-2.md).
- **--spectrum-hold=ミリ秒 \[2.9.18\]**: Hold time for the peak hold value (Reference3 and 5 of [OnSoundSpectrum](../../shiori-event/other/OnSoundSpectrum.md)) reported by --spectrum=. The range is 0–10000; the default is 500. Setting this to 0 disables hold (the peak is the same as the current value). Can be changed during playback.<br />
  Whenever the current value exceeds the peak, the peak rises to that value and its hold time is reset. It remains unchanged for the hold time, then falls at a rate of 100 (the full range down to 0) per second. If the current value catches up while the peak is falling, the same behavior starts again from that point.
- **--spectrum-skipbusy=false/true (=OFF/ON) \[2.9.33\]**: When reporting with --spectrum=, skip notifications while the ghost's script is playing or waiting to play. Defaults to false. Can be changed during playback.<br />
  Unless the script returned by [OnSoundSpectrum](../../shiori-event/other/OnSoundSpectrum.md) starts with `\C`, it interrupts any script that is playing or waiting to play (including scripts returned by other events). Because notifications are frequent, they may cancel scripts returned by events such as per-second events before their tags are executed. Specify this option to avoid that.<br />
  Skipped notifications are not delivered (another notification is sent at the next interval if the ghost is no longer busy). Notifications in which all levels are 0, sent on playback start or stop, are not skipped.<br />
  One limitation this option cannot prevent is that events such as OnSecondChange that occur while the ghost is playing a notification script become NOTIFY events that cannot return a script, as with ordinary events.
- **--eq=ゲイン:ゲイン:… \[2.9.29\]**: Graphic equalizer. List the gain (dB) for each band in order from the lowest-frequency band, separated by `:`. Example: `\![sound,play,bgm.wav,--eq=-12:-12:-6:0:0:0:6:12:12:12]`<br />
  The number of values determines the number of bands and must be 5, 10, 15, or 31. The frequencies of each band use the same [fixed table](bang-sound-option.note-2.md) as --spectrum-bands=, corresponding directly to the bands in the spectrum display (for 10 bands: 32, 64, 125, …, 16kHz). Gain can be an integer or decimal and may have a sign. It is clamped to the range -24 to 24 (out-of-range values become the nearest limit). If all bands are 0, the sound is not modified. Commas cannot be used as separators (they delimit arguments in `\![sound,…]`).<br />
  Using `--eq=` alone (with an empty value) resets all bands to 0dB. If the number of values is not 5, 10, 15, or 31, or any value cannot be read as a number, the entire setting is ignored and the current settings are retained.<br />
  The setting can be changed at any time during playback with [`\![sound,option,…]`](bang-sound-option.md). Changes are smoothed over about 10 milliseconds, so no clicks occur. The setting applies to that sound and is not retained when the same file is played again after playback ends.<br />
  Each band is designed so that the volume at its center frequency matches the specified gain (overlap with adjacent bands is compensated). Between bands, the gain shifts slightly more as it is raised or lowered (about 1dB at ±12dB). At many boundaries, the shift is toward the specified value of 0dB (slightly lower when boosting, slightly less attenuated when cutting). Bands too close to half the sample rate (the Nyquist frequency) have no effect.<br />
  The equalizer is applied before --volume and --balance, and before analysis for [OnSoundSpectrum](../../shiori-event/other/OnSoundSpectrum.md). Therefore, the equalizer is reflected in OnSoundSpectrum values. It has no effect on sounds such as MIDI and CD tracks, from which a waveform cannot be extracted.
- **--eq-preamp=ゲイン \[2.9.29\]**: Overall equalizer gain (dB). It is clamped to the range -24 to 24 (out-of-range values become the nearest limit); the default is 0. Use this to lower the overall level and prevent clipping when boosting bands makes the sound clip (become too loud and hit the limit). Can be specified separately from --eq= and takes effect even when --eq= is not specified. Can be changed during playback.
