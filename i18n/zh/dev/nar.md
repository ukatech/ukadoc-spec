# Creating Distribution Files

*For SSP 2.3.00 and later, the “Drop a folder to create updates2.dau or nar” feature used on this page is unavailable unless “Enable developer features” under “General” in “Settings” → “Baseware settings” from the owner draw (right-click menu) is turned on.*

This page explains how to create files (archives) for distribution.

It covers creating archives not only for ghosts, but also for additional shells, balloons, and other Ukagaka (伺か)/SSP-related content.

Please also read the “[Installation](../manual/install.md)” page under File Structure.

Note that this page does not explain how to create a ghost (or shell or balloon) itself.

This guide assumes that those steps have already been completed.

## Preparing the files

First, prepare the content to include in the archive (for a ghost, all the files that make up that ghost).

If you are developing by directly editing content installed in the baseware[※](nar.md#initial_installnarによるサイレントインストールについて), it is best to make a copy of the entire content in another location and use that copy as the distribution files before proceeding with the steps below.

For information about the files you need, refer to the “[Overall structure](../manual/directory.md)” page in the “File Structure” category in the menu on the left, as well as pages such as “[Ghosts](../manual/ghost.md)” and “[Shells](../manual/shell.md)”.

Files such as `install.txt`, `updates2.dau`, and `developer_options.txt` will be prepared later on this page, so you do not need them yet.

Next, remove files that users do not need. For example:

- Save data files for various SHIORI implementations (except when needed to set initial values, etc.)
- All profile folders (created in both ghost and shell folders; automatically removed by SSP)
- Development tools (such as Satorite and Resiba, included with Satori)
- (MATERIA only) profile.txt directly under the directory
- Configuration files generated by Windows, such as desktop.ini (SSP removes some of these automatically)
- Other development dictionary files, configuration files, log files, etc.

For SSP, you may want to configure `developer_options.txt`.

For details, see “[About developer_options.txt](nar.md#developer_optionstxtについて)” below.

## Creating the initial updates2.dau

Next, create the initial network update file (`updates2.dau`).

This mechanism detects problems such as corruption or tampering by checking for differences between the server-side and client-side file contents during a network update.

Therefore, you can skip this step if you do not plan to support the network update feature, or if the content does not support network updates in the first place (such as [additional files for ghosts](nar.md#ゴーストへの追加ファイルについて)).

In fact, a network update file is not required in an archive.

However, creating one reduces the work that the baseware must do on the user's computer during the first network update.

It is especially helpful to create one if the archive contains many files.

First, when creating `updates2.dau` with MATERIA or CROW, you must create an empty text file named `updates2.dau` in advance in the top-level directory (for example, for a ghost, the location containing the ghost folder, shell folder, readme.txt, etc.).

SSP creates it automatically.

Then start the baseware and drag and drop the folder containing `updates2.dau` and the files you want to update onto the main window.

With MATERIA or CROW, if `install.txt` is present, archive creation takes precedence and `updates2.dau` will not be created, so be sure to leave it out.

Conversely, with SSP, if you create `install.txt` first and then drag and drop the folder, you can create `updates2.dau` and the archive at the same time.

After you drag and drop the folder, a file named `updates2.dau` should be created in it (or already exist), and something should have been written to it.

You can open `updates2.dau` with a regular text editor such as Notepad, for example by right-clicking it, so check its contents (you do not need to understand the contents themselves).

## 准备install.txt

接下来，准备用于描述和设置安装内容的文件`install.txt`。

在最上层目录（例如，ghost的ghost文件夹、shell文件夹、readme.txt等所在的位置）准备一个名为`install.txt`的文本文件，并根据内容填写文件。

填写内容会因要分发的是ghost还是shell等而有所不同，请参阅[Install/Update设置](../descript/install/index.md)页面。该页面也提供示例。

## 打包为存档

终于到了打包为存档的阶段，不过到了这里，剩下要做的事情已经不多了。

这是因为baseware具备这样的功能：将包含`install.txt`的文件夹拖放到baseware上时，会把它打包为存档。

因此，要做的就是把之前准备好的整个文件夹拖放到baseware（当前正在运行的ghost）上。

这样应该会生成一个名为“\[文件夹名\].nar[※](nar.md#initial_installnarによるサイレントインストールについて)”的文件。这个文件就是用于分发的存档文件。

之后只要将这个nar文件上传到服务器或文件上传站点，就可以正式开始发布了。

## 关于developer_options.txt

使用SSP创建存档或`updates2.dau`时，可以在最上层目录（创建存档时放置install.txt的位置）准备一个名为`developer_options.txt`的文件，以设置处理对象文件。

关于写法的说明和示例，请参阅[Install/Update设置页面中关于developer_options.txt的章节](../descript/install/developer_options.txt/index.md)。

请注意，该文件只在SSP创建存档或`updates2.dau`时生效，因此在后文介绍的[ghost分发自动化系统](nar.md#ゴースト配布系自動化システムgdmについて)或其他baseware中创建这些文件时，不会生效。

## 关于ghost分发自动化系统(GDM)

ghost分发自动化系统(GDM)是一款辅助工具，可以一次性完成`updates2.dau`的创建、ghost打包为存档以及上传到服务器。

安装并正确设置后，本页面所述的大部分内容都不再需要手动处理。

目前可从「整备班」下载，详情如下。

[ghost分发自动化系统](http://ms.shillest.net/#TOOL)

关于详细的安装和设置说明，请参考以下网站（不需要参考其中「1」的内容）。

[ghost分发自动化系统(GDM)的使用方法](http://navy.nm.land.to/post/jidouhaihu.html)（[存档](https://web.archive.org/web/20260205013109/http://navy.nm.land.to/post/jidouhaihu.html)）

虽然名称中有“ghost”，但实际上它也可用于shell、balloon及其他各种内容的存档创建和网络更新文件上传。

此外，对于多个对象（例如ghost1、ghost2、shell1、shell2、shell3、balloon等），可以分别保存创建存档、网络更新等操作的设置，并在每次需要时选择要执行的操作，然后批量运行。

管理大量内容时，这款工具会非常有用。

初次安装和设置需要做的事情稍多，有些麻烦，但完成一次后，之后只需单击一下，就能完成多个内容的网络更新和存档更新，非常方便。

此外，它还能完全避免因创建`updates2.dau`后又修改文件，或以FTP ASCII模式上传等失误而导致的md5不匹配错误。

当然，通过适当设置，它也能有效防止混入不需要的文件。

请注意，前文提到的[developer_options.txt](nar.md#developer_optionstxtについて)是用于通过SSP创建nar或`updates2.dau`的设置文件，因此使用GDM创建时与它无关。

不过，GDM本身就可以设置要上传和不上传的文件，因此通常不需要该文件。

## 关于refreshinstall

如果install.txt中包含以下内容，安装时会执行特殊处理。

```
refresh,1
```

如果指定了此项，而要安装到的文件夹中已经存在文件，则不会覆盖文件，而是先将所有文件删除，再进行安装。

当更改文件夹或文件结构，导致覆盖后会残留不需要的文件时，可以使用此项。

但请注意，刷新安装会*连同存档数据等一起删除*。

可以通过以下方式指定刷新安装时要保留的文件。

```
refreshundeletemask,save1.txt:save2.txt
```

详细格式等内容，请参阅[Install/Update设置](../descript/install/index.md)页面。

## 关于随附分发balloon等内容

通过在install.txt中添加描述并配置文件，可以将balloon随ghost一同分发。

此外，在SSP中，除了balloon之外，还可以随包附带plugin和headline；这些内容也可以随shell而非ghost一同附带。

下面以随ghost附带balloon为例进行说明。

文件结构如下所示。

```filetree
+-(myghost)
　　+-install.txt
　　+-developer_options.txt (SSPのみ)
　　+-ghost
　　+-shell
　　+-(myballoon)
　　　　+-descript.txt
　　　　+-balloons0.png
　　　　:
　　　　:
```

此时，如果将install.txt写成以下内容，就可以在安装ghost的同时安装balloon。

```
charset,Shift_JIS
type,ghost
name,ゴースト名
directory,myghost（※ゴーストのフォルダ名。英数）
balloon.directory,myballoon（※バルーンのフォルダ名。英数）
```

这种情况下，balloon一侧不需要install.txt<br />
※即使有也会被忽略。考虑到单独分发，也可以将它放进去。

此外，如果安装后的balloon文件夹名与分发时的文件夹名不同，请按以下方式设置。

```
charset,Shift_JIS
type,ghost
name,ゴースト名
directory,myghost（※ゴーストのフォルダ名。英数）
balloon.directory,hoge_balloon（※インストール後のバルーンフォルダ名。英数）
balloon.source.directory,myballoon（※アーカイブ内のバルーンフォルダ名。英数）
```

这样，上例中名为myballoon的balloon文件夹<br />
在实际安装后会使用hoge_balloon作为文件夹名。

随附文件的refresh设置如下。

```
balloon.refresh,1
balloon.refreshundeletemask,hoge.png:huga.txt:...
```

要随包附带balloon以外的内容（仅限SSP），请将「balloon.directory」「balloon.source.directiory」「balloon.refresh」等项目中的「balloon」部分，分别替换为要随包附带的内容，也就是以下任一项：

- headline
- plugin
- calendar.skin
- calendar.plugin

然后按照上例中balloon的方式随包附带文件。

## About Additional Files for Ghosts

To create an archive of additional files (supplement) for a ghost, keep the ghost's original folder structure and include only the files you want to add.

For example, to add a file named "dic_supplement.txt" to ghost/master, the structure is as follows.

```filetree
+-(mysupplement)
　　+-install.txt
　　+-developer_options.txt (SSPのみ)
　　+-ghost
　　　　+-master
　　　　　　+-dic_supplement.txt
```

The contents of install.txt should be as follows.

```
charset,Shift_JIS
name,追加トークパッチ
type,supplement
accept,対象ゴーストの本体側名
```

## Packages for Multiple Installations

This method is exclusive to SSP.

You can create a package that installs multiple contents at once by creating an archive with a file structure like the following.

```filetree
+-(mypackage)
　　+-install.txt (package用)
　　+-(myghost1)
　　　　+-install.txt (myghost1用)
　　　　+-developer_options.txt (SSPのみ)
　　　　+-ghost
　　　　+-shell
　　　　:
　　+-(myghost2)
　　　　+-install.txt (myghost2用)
　　　　+-developer_options.txt (SSPのみ)
　　　　+-ghost
　　　　+-shell
　　　　:
```

Create an `install.txt` for the package in its folder, and put each set of contents inside that folder.

Each set of contents has its *own install.txt* and uses a standard installation structure that can also be archived on its own.

It may help to think of it as "packing" several sets of contents into folders, then adding a separate package `install.txt` as the label on the box.

Write the package install.txt in the top-level folder as follows.

```
charset,Shift_JIS
type,package
name,パッケージ名
```

Write each individual install.txt as usual (see [Install/Update settings](../descript/install/index.md), etc.).

When using [developer_options.txt](nar.md#developer_optionstxtについて), note that you should put it *in each set of contents*, not in the top-level folder.

The example file structure above contains two ghosts, but of course you can include any contents that are valid as an archive, not just ghosts.

However, be careful not to combine contents that specify an accept target, such as type,shell or type,supplement, if their targets differ.

## Silent Installation Using initial_install.nar

If you start SSP with a file named `initial_install.nar` placed in the same folder as ssp.exe, that nar file will be automatically installed over the existing files at startup without a confirmation dialog.

After installation completes, `initial_install.nar` is automatically deleted.

This feature is mainly intended for developers, and is useful when distributing SSP with ghosts or other contents bundled in its distribution package.

For example, if you want to create a distribution package that includes a specific ghost alongside SSP itself, simply place `initial_install.nar` in the same location as ssp.exe. The ghost will be automatically installed when the user starts SSP for the first time.

**対応:** SSP 2.7.52
