# 关于声音属性的元数据（meta.～）\[2.8.73\]

以 meta. 开头的声音属性会获取媒体文件中嵌入的标签信息（ID3、Vorbis Comment、MP4 元数据 atom、ASF 属性等）。所有这些属性均为只读。

**标签不存在或因某种原因无法获取时，会将该属性视为不存在。**请注意，这与[error](sound.error.md)那样返回空字符串不同，属性本身的读取会失败（行为与指定不存在的属性名时相同）。处理标签是否存在不确定的媒体时，请根据这一前提编写脚本。

此外，对于不含标签的格式，所有 meta. 属性自然都会获取失败。

\[2.9.32\] 对于 MP3 等文件中的 ID3（v1 / v2.2 / v2.3 / v2.4）、FLAC、Ogg Vorbis、Opus 注释以及 WAV、AVI 的 INFO 标签（包括 WAV 的 id3 块），SSP 不依赖 OS，而是自行读取。即使 OS 会误读的标签（例如被 OS 默认字符编码解读的 Shift_JIS 或 ISO-8859-1 标签、带有 unsynchronisation 或扩展头的 ID3v2、ID3v2.2、WAV 标签等）也能读取。SSP 无法读取的项目以及其他格式（如 MP4、WMA）仍从 OS 获取。<br />
对于未指定字符编码的标签（ID3v1、ID3v2 的 ISO-8859-1、WAV 和 AVI 的 INFO），SSP 会依次尝试 UTF-8 → Shift_JIS → OS 的默认字符编码。由于这是推测结果，尤其在非日语 OS 上，可能会混淆西欧语言和日语。<br />
现在会逐项获取：先由 SSP 读取，仅将无法读取的项目交由 OS 或媒体播放组件补充。因此，即使某个标签只能读取部分项目，其余项目仍可能由 OS 或媒体播放组件补充（例如，在某些环境中，如果标签没有专辑艺术家，系统可能会补入与艺术家相同的值）。
