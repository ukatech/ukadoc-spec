# 时区（--tz=）

- **local**: （默认）OS 时区。反映该日期的夏令时。
- **UTC / Z**: UTC。
- **+09:00 / +0900 / +09**: 相对于 UTC 的偏移量（最大 ±18:00）。
- **命名时区**: IANA 时区名称（如 `Asia/Tokyo`、`America/New_York`）或 Windows 时区名称（如 `Tokyo Standard Time`）。不区分大小写。反映该日期的夏令时。<br />
  时区规则使用 OS（Windows）的时区信息。IANA 名称会通过 Unicode CLDR 对照表转换为 Windows 名称。OS 中不存在的名称会返回 400（`invalid parameter`）。不会按 UTC 处理。

命名时区的规则受 OS 时区信息范围限制。对于 OS 信息中没有的旧规则（大多早于 2000 年代），会以 OS 所持信息中最早年份的规则代替。

## 夏令时切换前后

将时区中的日期时间（墙上时钟时间）转换为 UTC 时（读取不带时区的 ISO 8601 日期时间，或求出 [Add](internal_time.Add.md) 中以 `day` 或更大单位进行加法后的结果），夏令时切换前后会出现模糊时间。对于 `local` 和命名时区，无论时区位于西侧（偏移量为负）还是东侧（偏移量为正），都按以下规则处理。\[SSP 2.9.27\]

- **出现两次的时间**（夏令时结束、时钟拨回的日期）: 取较早的那个，即仍处于夏令时的时间。例如，`America/New_York` 的 `2026-11-01T01:30` 是 `2026-11-01T01:30:00-04:00`。
- **不存在的时间**（夏令时开始、时钟拨前的日期）: 使用切换前的偏移量读取，因此结果是拨前后的时间。例如，`America/New_York` 的 `2026-03-08T02:30` 是 `2026-03-08T03:30:00-04:00`，`Europe/Berlin` 的 `2026-03-29T02:30` 是 `2026-03-29T03:30:00+02:00`。

在 \[SSP 2.9.26\] 及更早版本中，对于偏移量为负的时区，不存在的时间会向前拨回 1 小时（`America/New_York` 的 `02:30` 会变成 `01:30-05:00`）。对于出现两次的时间，选择规则也会因时区位于东侧或西侧而相反。
