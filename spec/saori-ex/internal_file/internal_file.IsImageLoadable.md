# IsImageLoadable

**カテゴリ:** internal_file

画像ファイルを、SSPがどこまで取り扱えるかを調べる。ファイルをロードせずに、ヘッダと拡張子から判定する。サーフェスやバルーンの画像として使えるか、保存できるかを、ゴーストが事前に確かめるための関数。<br />
判定は、画像ファイルをSSPにドラッグ＆ドロップしたときに内蔵のピクチャビューアで開けるかの判定と同じ部品を使う。

- **Argument1**: ファイルのパス。相対パスはゴーストのフォルダ（ghost/master）が基準。区切りは`/`も`\`も書ける。ゴーストなしの呼び出しで相対パスを渡すと400（`ghost required`）。ファイルが無い（フォルダを含む）ときは400（`file not found`）。URLは受け付けない。

応答の`Result`は取り扱いのレベルで、次のどれか。

- **none**: 読めない。画像ではない、または未対応の形式。
- **read**: 読み取りのみ。SSPの内蔵ローダでは読めないが、OSの画像コーデック（WIC）が読める形式。ビューアなどで表示できるが、先頭の1コマだけで、サーフェスなどとしての保証はない。
- **embed**: ゴーストに組み込める。SSPの内蔵ローダで読める形式。
- **write**: 書き込みも可能。embedに加えて、SSPがその形式で画像を保存できる形式（PNG / BMP / JPEG / WebP）。アニメーションPNGと暗号化PNGは含まない。

後のレベルは前のレベルを含む（`write`ならば`embed`でもある）。判定は実際のローダと同じく先頭のヘッダを優先し、ヘッダで分からなければ拡張子を見る。EXE / DLL（アイコンの取り出し用）は画像と数えない。<br />
どのレベルになるかはSSPの版やOSの環境で変わりうる。今後、レベルが増えることがある。

## 記述例

```
Argument0: IsImageLoadable
Argument1: image/bg01.png

→ 200
　Result: write
```

**対応:** SSP 2.9.27
