# 内蔵モジュールの共通規約

SSPが内蔵している、名前が`internal_`で始まるモジュールの共通の決まりです。（同じ名前のSAORI DLLと衝突しないように、`internal_`で始まる名前にしています。）<br />
これらのモジュールはDirect SSTPからだけ呼べます。DLLとしてloadすることはできません。

## 関数と引数

`Argument0`が関数名（大文字小文字は区別しない）、`Argument1`以降がその関数の引数です。知らない関数名は400（`unknown function`）です。<br />
引数は、関数ごとに決まった数の**位置引数**と、その後ろに並べる**オプション**（`--名前=値`）からなります。

- 位置引数の位置にある値は、`--`で始まっていてもオプションとしては読まず、データとして扱います。
- オプションは位置引数より後ろにだけ書けます。省略できる位置引数を飛ばしてオプションを書くときは、空の引数を置いてください。
- オプションの名前は大文字小文字を区別しません。同じ名前を2回書くと後のものが有効です。
- 位置引数より後ろにある`--`で始まらない値、関数が受け付けないオプションは400（`invalid parameter`）です。
- \[SSP 2.9.25\] 位置引数の数が決まっていない関数（[internal_fileのMediaInfo](internal_file/internal_file.MediaInfo.md)）は、2番目以降の位置で最初に`--`で始まる値から後ろをオプションとして読みます。
- どの関数も[`--async=識別子`](async.md)を受け付けます。

```
Argument0: Digest
Argument1: sha256
Argument2: SGVsbG8=
Argument3: --data-in=base64
Argument4: --out=base64
```

## バイト列の入力の形式

ハッシュなどはバイト列を扱いますが、SAORIで渡せるのは文字列です。バイト列を受け取る引数にはそれぞれ名前（`data`、`key`、`password`、`salt`、`ciphertext`、`signature`、`a`、`b`など。各関数の説明を参照）があり、`--名前-in=形式`でその引数の読み方を変えられます。例：`--key-in=hex`、`--data-in=base64`。<br />
オプションで渡すバイト列（`--aad=`、`--iv=`、`--info=`）も同じで、`--aad-in=hex`のように読み方を変えられます。

- **text**: 文字列を、`--charset=`の文字コード（既定は**UTF-8**）のバイト列にする。要求の`Charset`ではない（送り手の文字コードによらず、Web APIの署名などと同じ値になるように）。その文字コードで表せない文字があれば400（`invalid encoding`）。
- **hex**: 16進。大文字小文字はどちらでもよい。奇数桁・16進以外の文字は400（`invalid encoding`）。
- **base64 / base64url**: パディング（`=`）はあってもなくてもよい。どちらの形式でも、base64とbase64urlの両方の文字（`+ / - _`）を読む。それ以外の文字・パディングの誤りは400（`invalid encoding`）。
- **base32**: RFC 4648。大文字小文字・パディングの有無は問わない。不正な文字は400（`invalid encoding`）。
- **url**: パーセントエンコードを戻したもの。`+`は空白に戻さない。`%`の後ろが16進2桁でなければ400（`invalid encoding`）。
- **bech32**: \[SSP 2.9.14\] BIP-173のbech32（nostrの`npub1...` / `nsec1...`など。bech32mは読めない）。データの部分をバイト列にする。`1`より前の部分（hrp。`npub`など）は見ないので、種類を確かめたいときはスクリプトで文字列の先頭を見ること。大文字だけ・小文字だけのどちらでもよい。混在・チェックサムの誤り・不正な文字は400（`invalid encoding`）。長さ（BIP-173の90文字）の制限はない。
- **file**: 値をファイルのパスとして、ファイルの中身を読む。`internal_crypto`の`Digest` / `HMAC`の`data`だけで使える。<br />
  相対パスはゴーストのフォルダ（ghost/master）が基準。ゴーストなしの呼び出しで相対パスを渡すと400（`ghost required`）。ファイルが無ければ400（`file not found`）、途中で読めなくなったら500（`file read failed`）。

既定の形式は引数ごとに決まっています（各関数の説明を参照）。デコードした後のデータは1つの引数あたり8MBまで（`too large`）ですが、Direct SSTPの要求そのものが1MBまでなので、実際にはそれより小さくなります。`file`は少しずつ読むので大きさの上限はありません。

## バイト列の出力の形式

バイト列を返す関数は、`--out=形式`で結果の書き方を変えられます。既定の形式は関数ごとに決まっています。出力の既定の形式は、同じ名前の入力の既定の形式に合わせてあるので、出した値をそのまま別の関数に渡せます。

- **hex**: 16進（小文字）。
- **HEX**: 16進（大文字）。
- **base64**: パディングあり。
- **base64url**: パディングなし。
- **base32**: RFC 4648。パディングあり。
- **url**: RFC 3986の非予約文字（`A-Z a-z 0-9 - . _ ~`）以外をすべて`%XX`（大文字）にする。
- **bech32**: \[SSP 2.9.14\] BIP-173のbech32（小文字）。hrp（`npub`など。1～83文字）を`--hrp=`で指定する。`--hrp=`を受け付けるのは[internal_dataのConvert](internal_data/internal_data.Convert.md)だけで、ほかの関数で`--out=bech32`にすると400（`invalid parameter`）。
- **text**: `--charset=`の文字コード（既定はUTF-8）の文字列として返す。その文字コードとして正しく戻せないバイト列や、NUL・改行（SAORIのヘッダに書けない）を含むときは500（`not text`）。<br />
  応答は要求の`Charset`の文字コードで返るので、そこで表せない文字は`?`に化けます。どんな文字でも受け取れるように、要求は`Charset: UTF-8`で送ってください。

`--charset=`には文字コードの名前（`UTF-8`、`Shift_JIS`、`EUC-JP`など）を書きます。知らない名前やUTF-16は400（`invalid parameter`）です。

## 応答と失敗理由

成功すれば200で`Result`に結果が入ります。結果が空文字列のときは204です。真偽を返す関数は、200で`1`（真）または`0`（偽）を返します。「一致しない」などは失敗ではありません。<br />
失敗時の[ErrorDescription](directsstp.md)には、共通のもののほかに次のものがあります。

- **unsupported algorithm**: 400。知らないアルゴリズム名。
- **invalid encoding**: 400。`--名前-in=`の形式として読めない。圧縮データが壊れている。
- **invalid key**: 400。鍵の長さがアルゴリズムに合わない。公開鍵暗号の鍵として読めない、鍵の種類が方式に合わない。
- **out of range**: 400。数値・日時が扱える範囲の外。
- **too large**: 400。データが大きすぎる。
- **file not found**: 400。`--data-in=file`のファイルが無い。
- **not text**: 500。`--out=text`で文字列に戻せない。
- **file read failed**: 500。ファイルを途中で読めなくなった。
- **authentication failed**: 500。復号できない（暗号文の改ざん・鍵の違いなど）。JWTを検証できない。
- **expired / not yet valid**: 500。JWTの有効期限（`exp`）が切れている / 有効になる時刻（`nbf`）より前。
- **internal error**: 500。ベースウェア内部の想定外の失敗。
