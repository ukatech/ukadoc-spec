# 共通鍵暗号（Encrypt / Decrypt）

アルゴリズムは次のとおり（名前のハイフン・アンダースコアの有無と大文字小文字は区別しない）。これ以外は400（`unsupported algorithm`）。

- **aes-256-gcm（推奨） / aes-128-gcm / chacha20-poly1305**: 認証付き暗号。改ざんされた暗号文は復号できない。暗号文の形は「nonce（12バイト）＋暗号文＋認証タグ（16バイト）」。
- **aes-256-cbc / aes-128-cbc**: PKCS#7のパディング。暗号文の形は「IV（16バイト）＋暗号文」。改ざんを検出できないので、ほかのシステムとやりとりするときだけ使うこと。
- **aes-256-ctr**: 暗号文の形は「IV（16バイト）＋暗号文」。改ざんを検出できない。
- **chacha20**: \[SSP 2.9.14\] 認証の付かないChaCha20（RFC 8439。nonceは12バイト、ブロックのカウンタは0から）。暗号文の形は「nonce（12バイト）＋暗号文」。改ざんを検出できないので、ほかのシステム（nostrのNIP-44など、MACを別に付ける方式）とやりとりするときだけ使うこと。

鍵（key）の長さはアルゴリズムの鍵長ちょうど（AES-256とChaCha20は32バイト、AES-128は16バイト）でなければ400（`invalid key`）。パスワードから鍵を作るときは[DeriveKey](internal_crypto.DeriveKey.md)を通してください。<br />
nonce / IVは暗号化のたびに乱数で作って暗号文の先頭に付ける。`--iv=`（nonce / IVを指定する）と`--pack=none`（先頭に付けない）は、ほかのシステムがnonceを別に受け渡す場合のためだけのものである。**同じ鍵で同じnonce / IVを2回使うと、GCM・ChaCha20-Poly1305・CTRは暗号として破れる**（平文が漏れ、改ざんもできるようになる）。`--iv=`に固定の値を書いて使い回さないでください。
